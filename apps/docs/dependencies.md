## Bundled notices

Production builds collect original LICENSE/COPYING/NOTICE text from the resolved dependency graph and include upstream/published-source links:

- Browser: `/app/licenses/THIRD-PARTY-NOTICES.txt`, plus Manrope OFL and KaTeX font notices.
- Docs: `/docs/licenses/THIRD-PARTY-NOTICES.txt`; docs use local search, not a hosted Algolia account.
- Server image: `/app/apps/server/dist/THIRD-PARTY-NOTICES.txt` (filesystem, not a public API).
- Native installers: platform-filtered Cargo notices, bundled font notices and Sparkle license, generated by the native packaging scripts.

The traversal is intentionally conservative and can include reachable packages not used in the final bundle. It does not include every optional platform package. Missing license text fails the build. When an npm archive omits its notice, exact-version fallback texts are retained under `scripts/licenses/` with source URLs and verified hashes; dependency changes require explicit review. `standardwebhooks` 1.1.1 declares MIT in npm metadata, while its published gitHead's repository license is Apache-2.0; the upstream text is retained and that discrepancy remains a licensing-review item, rather than silently relabelling it MIT.

Public Helious application source is Apache-2.0. That does not relicense dependencies, logos or trademarks. For prebundled components, retain the corresponding upstream source reference and notices (including Mermaid's ELK dependency); assess reciprocal/distribution obligations for the artifact actually shipped. API/provider contracts, marketing artwork, third-party tool logos and the private website have separate terms and remain outside this public license grant. A notices generator is attribution evidence, not blanket legal clearance.
